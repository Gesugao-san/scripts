# Директивы каналов Tixati

Пересказ и разбор официальной справки
[Channel Directives](https://support.tixati.com/channel%20directives)
своими словами, с пояснениями. Если что-то расходится с оригиналом, верен
оригинал: Tixati обновляется, а справка местами очень лаконична.

## Что это такое

Директива — это служебная строка, которая начинается с `##`. Её вписывают
в текст канала, и Tixati понимает её как настройку, а не как обычный текст. Так без отдельных диалогов настраивается
поведение канала: права, частота рассылок, тема, приветствие, зеркалирование
раздач.

Директиву можно вписать в одно из двух мест:

| Место | Что там работает |
|---|---|
| **Share** — текст, которым ты делишься в канале | только директивы зеркалирования (`##mirror…`) и разметка сегментов (`##-`, `##^`) |
| **Channel Info** — описание канала | все остальные директивы (`##stream…`, `##ctrl…`, `##topic…` и т.д.) |

Справка прямо говорит, что вторая группа работает **только** в Channel Info:
`##ctrl:…` в тексте Share не сработает. Работают ли директивы Share в
Channel Info, справка не уточняет. Кто именно может править Channel Info,
тоже не сказано: судя по `##topic`, который может менять только владелец,
права зависят от директивы.

Общий вид:

```
##имя:параметр=значение&параметр=значение
```

- одна директива — одна строка;
- несколько параметров одной директивы склеиваются через `&` (это прямо
  показано для `##ctrl`);
- значения-списки перечисляются через запятую, без пробелов.

## Уровни доступа

Многие директивы принимают уровень доступа пользователя. В справке
упоминаются (от низшего к высшему):

```
normal → trusted → vip → star → mod (модератор) → manager → owner (владелец)
```

`mod+` в справке означает «модератор и выше». Точный порядок `mod` и
`manager` справка явно не задаёт. Порядок выше — моя трактовка по смыслу
названий. Где важно, проверяй на практике.

## Директивы для Share (зеркалирование)

Зеркалирование автоматически публикует в канал списки твоих раздач и
поддерживает их в актуальном состоянии: добавил торрент — он появился в
канале.

### Зеркало по состоянию

```
##mirror:transfers
```

Публикует весь список передач (transfers).

Можно публиковать только передачи в определённом состоянии:

| Директива | Что публикуется |
|---|---|
| `##mirror:complete` | завершённые |
| `##mirror:standby` | в режиме ожидания |
| `##mirror:seeding` | раздаваемые |
| `##mirror:downloading` | скачиваемые |
| `##mirror:queued` | стоящие в очереди |
| `##mirror:offline` | отключённые |

### Зеркало категории

```
##mirror:cat=123456
```

Публикует одну категорию передач по её числовому ID. Так удобно делиться,
например, только категорией «Фильмы», а не всем списком.

### Частота обновления зеркала

```
##mirror:complete&ttl=1800
```

Параметр `ttl` задаёт, как часто зеркало обновляется, в **секундах**.
В примере это 1800 с, то есть раз в 30 минут. Значение по умолчанию справка
не называет. Слишком маленький `ttl` зря нагружает канал.

### Зеркало другого канала

```
##mirror:dsc:HASHID
```

Повторяет в твоём канале содержимое **другого** канала. `HASHID` — это
52-символьный Hash-ID из ссылки-приглашения `dsc:HASHID?dn=ИМЯ`. Его можно
достать из ссылки командой
`tixati-channel-key.py decode "dsc:…?dn=…"` из этой же папки.

> В справке этот параметр назван «channel key», но по виду и по ссылке
> `dsc:` это именно Hash-ID канала, а не приватный ключ. Приватный ключ
> (Owner Control Key) никуда вписывать не нужно и нельзя: кто его знает,
> тот управляет каналом.

### Сегменты для инкрементальных обновлений

```
##-
строки сегмента
##-
```

`##-` отмечает границы сегментов. Строки между двумя маркерами образуют
один сегмент. Это позволяет Tixati рассылать обновления по частям:
изменился один сегмент — уходит только он, а не весь текст.

```
##^ строка заголовка
```

`##^` отмечает строку **заголовка**. Она прикладывается к **каждому**
сообщению с обновлением, так что получатель всегда видит контекст (например,
название раздела), даже если пришёл только один сегмент.

Справка описывает эти маркеры одной строкой. Детали поведения (вложенность,
ограничения размера) там не раскрыты.

## Директивы для Channel Info

### Стриминг

```
##stream:minlevel=manager
```

Минимальный уровень доступа, с которого пользователю разрешён стриминг.
По умолчанию — `manager`, то есть обычным участникам стриминг закрыт.

```
##stream:uid=UID
##stream:uid=UID1,UID2,UID3
```

Белый список: разрешить стриминг конкретным пользователям независимо от
уровня. `UID` берётся так: правый клик по пользователю в чате канала.
Несколько UID перечисляются через запятую.

### Видимость в общем списке

```
##adv
```

Канал появляется в результатах, когда другие пользователи нажимают
**Gather Channels** (сбор списка каналов). Без `##adv` канал можно найти
только по ссылке-приглашению. Похоже, это та же настройка, что и галочка
**Advertise in channel list** при создании канала.

### Тема

```
##topic:Текст темы
```

Задаёт тему канала. Менять её может только **владелец**.

### Приветствие (MOTD)

```
##motd_begin
Добро пожаловать!
1. Не флудить.
2. Раздавать то, что скачал.
##motd_end
```

Всё между `##motd_begin` и `##motd_end` — «сообщение дня» (message of the
day). Его видит каждый, кто заходит в канал. Удобно для правил.

### Управление: `##ctrl`

Параметры `##ctrl` задают права и частоту рассылок. Каждый можно писать
отдельной строкой или склеить в одну через `&`.

| Параметр | Что делает | Единицы / формат |
|---|---|---|
| `dl=normal` | уровень доступа, который получает **новый** пользователь | уровень доступа |
| `ir=15` | как часто рассылается **информация о канале** | секунды между рассылками |
| `sr=40,30,20,15,12` | как часто рассылаются **раздачи (shares)** | секунды между рассылками, для 5 уровней |
| `mr=30,30,20,10,10` | **максимальная** частота рассылок | рассылок в минуту, для 5 уровней |
| `pr=50` | **минимальная** частота рассылок | секунды между рассылками |
| `sttl=123` | время жизни кэша пользователей | появилось в версии 2.89; единицы в справке не указаны |

Списки в `sr` и `mr` идут строго в таком порядке уровней:

```
normal, trusted, vip, star, mod+
```

То есть `sr=40,30,20,15,12` означает: обычные участники рассылают раздачи не
чаще раза в 40 с, доверенные — раз в 30 с, vip — раз в 20 с, star — раз в
15 с, модераторы и выше — раз в 12 с. Чем выше уровень, тем чаще можно.

Обрати внимание: у `sr`, `ir` и `pr` единицы — **секунды между** рассылками
(больше число — реже), а у `mr` — **рассылки в минуту** (больше число —
чаще). Их легко перепутать.

По умолчанию `pr` = наибольшее значение из `sr` плюс 10. Для примера выше
это 40 + 10 = 50, поэтому `pr=50` в примере совпадает с умолчанием.

Всё сразу одной строкой:

```
##ctrl:ir=15&sr=40,30,20,15,12&mr=30,30,20,10,10&pr=50&dl=normal
```

### Дополнительный параметр: `##extra`

```
##extra:ЗНАЧЕНИЕ
```

Задаёт дополнительный параметр для конкретного канала. Значение должно быть
**подписано**. Чем и как подписывать, справка не объясняет, так что без
официальных инструкций эта директива, по сути, недоступна.

### Форум

```
##forum:aal=normal
```

Минимальный уровень доступа, с которого сообщения пользователя на форуме
канала **одобряются автоматически**. Сообщения от пользователей ниже этого
уровня ждут ручного одобрения.

## Пример Channel Info целиком

```
##adv
##topic:Обмен open-source дистрибутивами
##motd_begin
Привет! Здесь только свободное ПО.
Раздавай то, что скачал.
##motd_end
##ctrl:dl=normal&ir=15&sr=40,30,20,15,12&mr=30,30,20,10,10
##stream:minlevel=vip
##forum:aal=trusted
```

Что получится: канал виден в Gather Channels, у него задана тема и
приветствие с правилами. Новые участники получают уровень `normal`. Частоты
рассылок как в примере справки, `pr` по умолчанию (50). Стриминг разрешён
с уровня `vip`. Сообщения на форуме от `trusted` и выше публикуются без
модерации.

## Чего в справке нет

- значений по умолчанию для большинства директив (кроме `stream:minlevel`
  и `ctrl:pr`);
- ограничений на длину директив и текста;
- единиц для `ctrl:sttl`;
- способа подписи для `##extra`;
- точного порядка уровней `mod` / `manager`.

Если понадобится что-то из этого, проверяй на тестовом канале.
